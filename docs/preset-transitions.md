# Host preset transitions

State-file preset loads prepare a separate, activated instance on the UI thread. The playing instance is never locked for `load_state`. Creation, state rejection or activation failure leaves the old instance and label in place. Native program/bank selectors and parameter-list presets retain their existing behavior; ARA document restoration remains project-editor work.

The transport updates the instance registry and hands off only the selected node under the engine boundary lock. It retains the existing graph, slot ports, sidechain, bypass, mix and delay-pad histories. Automation values are invalidated for that target so constant curves are resent. Delay compensation observes the new plugin's reported latency normally.

Instrument voices replay their key, velocity, fine tuning, note levels, voice IDs and current glide. MIDI caching uses fixed storage, with sustain, pitch, pressure and poly pressure replay; MPE setup precedes replay. Bank/program changes are not replayed over the selected preset. Arbitrary RPN/NRPN transactions are not reconstructed. Pending releases follow replayed MIDI. Pause/stop clears cached held notes. A five-millisecond ramp from the last output sample reduces switch discontinuities; it is not a crossfade of two running plugins and does not preserve old reverb tails or oscillator/envelope phase.

The old Hosted object retains its editor until all renderer references have gone. UI housekeeping then closes the editor and uses the existing UI-thread retirement queue for destruction. An open replacement editor is prepared before the transport sees the instance. Rack editors use their existing lazy reopening behavior. Native window movement and listening still require hands-on acceptance.

Existing host parameter Undo targets the replacement through refreshed parameter bindings. This change does not add whole-preset entries to project Undo or preserve a plugin's private editor undo stack. Save presets before switching when an edited sound must be recovered. No new control or Workspace Visibility option is necessary: this changes the existing load commands.

Validation uses synthetic state rejection and delayed loads, held-note/release and unaffected-track checks, sustain/MPE message ordering, ramp continuity, constant automation and effect routing. The optional `installed_editor_with_app_parameter_tick_and_queue` diagnostic defaults to the prepared path; `LEMON_STRESS_IN_PLACE=1` deliberately reproduces the old contention path. It asserts audible output as well as finite samples and underrun counts. Set `LEMON_STRESS_HEADLESS=1` for device-free, editor-free testing. Third-party plugin internal browsers, global locks inside plugins, physical audio devices and Mac/Linux runtime performance are outside these Windows headless claims.
